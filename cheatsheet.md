# Шпаргалка до захисту — лабораторна робота №2

## HTML

HTML задає структуру та зміст сторінки. `header` містить назву дисципліни, `nav` — навігацію, `main` — основний вміст, `article` — самостійну роботу, `section` — тематичні розділи, `aside` — допоміжні посилання, `footer` — авторський підпис. Посилання створює елемент `a` з атрибутом `href`. `ul` описує неупорядкований список, `ol` — упорядкований.

## Git і GitHub

Git — розподілена система керування версіями. Локальний репозиторій зберігає файли та історію комітів; GitHub — віддалена копія. Коміт фіксує стан проєкту. Гілка дозволяє вести окрему лінію змін.

```sh
git --version
git init
git add .
git commit -m "IP labs init"
git branch -M main
git remote add origin https://github.com/USERNAME/ip_labs.git
git push -u origin main
```

`git pull` отримує зміни з remote, `git push` надсилає локальні коміти.

## Netlify

Netlify підключається до репозиторію GitHub і автоматично публікує новий deploy після push до вибраної гілки. Для цього статичного сайту не потрібна команда збірки; publish directory — корінь проєкту (`.`). Після першого розгортання потрібно відкрити видану HTTPS-адресу та перевірити головну сторінку і навігаційні посилання.

## Контрольні питання

- Атрибути `a`: `href`, `target`, `rel`, `download`, `title`; також можуть застосовуватись `hreflang`, `type`, `referrerpolicy`.
- Нова вкладка: `target="_blank"`, разом із `rel="noopener noreferrer"`.
- Завантаження: атрибут `download` у посиланні на файл, наприклад `<a href="file.pdf" download>Завантажити</a>`.
- Якір на сторінці: `href="#section-id"`, а ціль має `id="section-id"`.
- Відносне посилання залежить від поточного документа/кореня сайту; абсолютне містить повну адресу, наприклад `https://example.org/path`.
- Git розподілений, бо робочі копії з історією зберігаються у кожного учасника, а зміни синхронізуються між remote і локальними репозиторіями.
- Типова структура: робоче дерево файлів, індекс (staging area) і локальна база об’єктів/історії `.git`; віддалений репозиторій — окремий remote.
- Дворівневе меню: вкладений список у пункті верхнього рівня, наприклад `ul > li > ol > li > a`.
- Початковий push: створити remote repo; `git init`; `git add`; `git commit`; перейменувати гілку на `main` (якщо потрібно); додати `origin`; виконати `git push -u origin main`; перевірити файли на GitHub.
